# 流量与 pcap 验证

## 适用范围

非 `T` 类、非 `F` 类告警默认视为流量 / 规则类告警，需要确认是否有 pcap。

## 有 pcap 时

使用脚本或 `tshark` 验证实际流量。推荐命令：

```bash
python3 scripts/analyze_alert.py --pcap <pcap> --src <ip> --dst <ip> --term "<feature>" --json
```

必要时补充：

- `--sport <port>`
- `--dport <port>`
- `--count 10`

必须确认：

- 命中特征在请求侧还是响应侧。
- 是否存在完整会话、请求响应闭环和结果性证据。
- 是否有执行、回显、下载、落地、上传成功、回连建链或异常成功响应。
- 当前内容是否可由正常业务逻辑产生。

## 无 pcap 时

基于 JSON 输出降级结论，并同时询问：

> 是否有对应的 pcap 文件？如有请提供路径，可做进一步验证。

强制注明：

> 无 pcap，仅基于 JSON 研判，结论供参考。

无 pcap 时不得输出“攻击成立”“利用成功”或高置信强结论。

## 请求 / 响应侧判断

1. 特征出现在请求侧时，优先按攻击输入分析。
2. 特征仅出现在响应侧，且请求侧无恶意输入支撑时，优先考虑误报、正常业务回显、平台详情展示、日志 / 样本 / 告警内容返回。
3. 不得仅凭响应内容中的命中特征判定攻击成立。

## 判定原则

- 特征出现在请求侧，且行为链成立：倾向“攻击尝试 / 可疑攻击行为”或“攻击成立”。
- 特征仅出现在响应侧，且可被业务逻辑解释：倾向“误报”。
- 上下文存在扫描、探测、利用链路，但无结果性证据：判“攻击尝试 / 可疑攻击行为”。
- 无法判断请求 / 响应位置，或缺少上下文：判“待进一步确认”。

## 业务合理性场景

以下场景必须额外判断内容是否可能由正常业务产生：

- 管理后台
- 安全产品平台
- 日志检索 / 事件详情接口
- 文件上传 / 下载系统
- 认证系统 / 单点登录 / 票据交换
- 返回样本、规则、情报、漏洞详情的接口
