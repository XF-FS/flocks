# 告警研判

## 摘要优先

所有 JSON 告警必须先执行：

```bash
python3 scripts/alert_summary.py <json_file>
```

用途：提取默认摘要、获取 `suuid`、判断告警类型、提取基础研判字段。

禁止：

- 禁止直接读取完整 JSON 人工分析。
- 禁止一开始就提取大字段，如 `raw_data`、`resp_body`。
- 禁止跳过字段提取脚本直接输出结论。

## threat.level 分流

| threat.level | 类型 | 处理方式 |
| --- | --- | --- |
| `attack` | 攻击检出 | 进入攻击研判流程，输出误报 / 攻击尝试 / 攻击成立 / 待确认 |
| `risk` | 风险检出 | 若 `threat.result == "success"`，聚合到脆弱性模块；否则评估风险来源 |
| `suspicious` | 可疑检出 | 结合上下文判断是否为攻击行为或正常业务 |
| `action` | 行为检出 | 非攻击告警，确认是否授权，必要时建议加白 |

`action` 告警不得直接判为“攻击成立”或“攻击尝试”。若无明显异常，结论倾向“正常行为 / 误报 / 待确认”。

## 四步研判法

必须按以下行为证据链研判：

1. 触发原因：哪个字段、哪段特征、命中位置在哪里。
2. 实际内容：流量或字段里实际传输了什么，特征在请求侧还是响应侧，是否存在会话闭环。
3. 行为成立性：告警声称的行为是否真的发生，是否有执行、回显、下载、落地、控制、外联等证据。
4. 攻击目的性与业务合理性：判断恶意利用、扫描、安全测试、业务传输或正常数据内容。

规则命中不等于攻击成立；异常请求不等于风险落地；恶意载荷不等于利用成功。

## suuid 分流

| suuid 前缀 | 类型 | 下一步动作 |
| --- | --- | --- |
| `T` | 情报类 | 读取 `docs/threatbook.md`，查询 ThreatBook 并核验时间有效性 |
| `F` | 文件类 | 读取 `docs/threatbook.md`，提取 hash 并查询沙箱 / 多引擎 |
| 其他 | 流量 / 规则类 | 读取 `docs/traffic-pcap.md`，确认是否有 pcap |

仅允许进入一条主路径。

## 字段不足时补提

默认摘要不足以支撑研判时，先列字段：

```bash
python3 scripts/alert_summary.py --list-fields
```

再按需补提指定字段。字段不足不得直接下结论。

优先补提字段：

- 告警基础：`suuid`、`threat.level`、`threat.name`、`threat.result`、`time`、`input_time`
- 网络五元组：`src_ip`、`src_port`、`dst_ip`、`dst_port`、`proto`
- HTTP 内容：请求方法、URI、Host、User-Agent、Cookie、请求体、响应码、响应体摘要
- 文件 / hash：`hash`、`file_upload_data.hash`、文件大小、文件类型、文件动作
- 证据字段：连接状态、收发字节数、收发包数、命中特征位置

## Step 3：辅助搜索确认

### 搜索告警名称

告警研判输出结论前，必须使用 websearch 搜索告警名称，用于校验攻击类型、常见误报场景、利用方式和结论方向。

### 无法判断时搜索攻击访问路径

以下情况需要继续追加搜索：

- 告警名称或攻击类型语义不明确。
- 四步研判后仍无法确认攻击访问路径。
- 需要判断是否属于已知漏洞利用场景。
- 需要确认常见误报场景或公开利用方式。

判断漏洞场景时，可使用以下异常特征作为搜索关键词：

- 异常请求路径，如管理接口、上传接口、插件路径、框架特征路径、漏洞利用路径。
- 异常请求内容，如命令执行参数、SQL 注入片段、反序列化数据、模板表达式、路径穿越、WebShell 内容。
- 异常返回内容，如命令回显、报错栈、文件写入路径、上传成功信息、WebShell 管理端标识。
- 产品名、组件名、接口路径、参数名、错误信息与 payload 组合。

搜索结果只能作为辅助参考，不得替代当前告警证据。

## 结论分级

最终结论只能选择一项：

1. 误报
2. 攻击尝试 / 可疑攻击行为
3. 攻击成立
4. 待进一步确认

## 强结果性证据

存在以下强结果性证据时，即使没有 pcap，也可以基于 JSON 输出“攻击成立”或“利用成功”，但必须说明证据来源于 JSON 字段：

- 上传木马、WebShell、恶意脚本或可执行文件成功。
- WebShell 访问、连接、命令交互或管理端返回成功。
- 命令执行回显、执行结果、子进程启动记录。
- 文件写入、释放、落地、持久化动作成功。
- 外联下载成功、C2 回连成功、反连建链成功。
- 数据库写入 WebShell、UDF / CLR / OLE 执行动作成功。
- 服务端响应明确证明利用达成，如成功写入路径、返回执行结果、返回 shell 管理标识。

只有攻击输入、恶意 payload、规则命中或情报命中，但没有结果性证据时，不得表述为“攻击成立”或“利用成功”。
